# Create: Media Systems

様々なメディアをゲーム内で再生可能にするNeoforge向けMod

## 対応環境

- Minecraft 1.21.1 / NeoForge 21.1
- Create 6.0.10^
- Java 21

## ビルド

```bash
./gradlew build
```

## 舞台照明

ムービングヘッドライトはスポット／ビーム、レーザープロジェクターは単線／扇／光の面を照射します。照明制御卓から6グループに分けて操作でき、右クリックで開く設定GUIはありません。

1. 照明制御卓を同じ向きで横4×奥2に並べ、後列の上に照明制御卓モニターを4枚置きます。
2. 「照明リンク」で完成した卓を右クリックし、続けて灯具を右クリックすると、卓で選択中のグループに接続します。Shift＋右クリックで灯具の接続を解除できます。
3. 同じリンクで再生機器を右クリックすると音源を接続します。Blu-rayプレーヤーは音声と映像を接続し、Shift＋右クリックなら映像だけを接続します。

卓と灯具の操作は、素手またはCreateのレンチを持って行います。操作部を狙うと水色の枠と設定名・値が表示され、操作すると金色に点灯します。保存・適用の通知は操作後もしばらく表示されます。

| 操作部 | 操作 |
| --- | --- |
| 調光フェーダー・照射方向パッド | 右クリックを押したまま、視線を動かして調整 |
| モニターの項目 | 右クリックまたはスクロールで切替。左からグループ、点灯・音声連動・光の形、配色、動き・追従対象 |
| RGBパッド | 右クリックで選択中の色を変更。Shift＋右クリックで色を追加（最大8色） |
| RGBモニター上部の色枠 | 編集する色を選択。下の項目で色数・配り方・映像連動を変更 |
| RGBつまみ | スクロールで調整。Shiftを押すと細かく調整 |
| 右側の3つのつまみ | 左から照射距離・広がり角度・動く速さを調整 |
| 照射距離のつまみ | スクロールで1ずつ、Shift＋スクロールで10ずつ変更。Ctrlを併用すると全グループを同じ量だけ変更（各グループの上下限まで） |
| 中央の演出ボタン | 「基本」で固定・往復・色送り・扇回転・光の面・追従を選び、右クリックで選択中グループに適用 |
| 「保存枠」ボタン | 自分で保存した6枠に切替。「空き」と表示された枠は未登録 |
| 「保存」ボタン | 保存→保存先の枠を右クリック。選択中グループの設定を上書き保存。「中止」でキャンセル |
| 灯具本体 | スクロールでグループ、Shift＋スクロールで並び順、Ctrl＋スクロールで個別色を変更 |

複数色は「交互・順番」「左右に分割」「グラデーション」「灯具ごと」で割り当てます。並び順は灯具を接続した順で、灯具本体から変更できます。レーザーの扇・面では、線の並びにも配色を適用します。

基本の演出は色・明るさ・照射距離・手動の照射方向を維持して、光の形と動き・連動方法を切り替えます。「追従」は操作したプレイヤーを対象にします。保存枠はグループの設定一式を記憶し、別のグループにも適用できます。保存枠を使用しても基本の演出は残ります。

音声連動は全音域・低音・中音・高音を選び、音の強弱に明るさや動く速さを反応させます。映像連動は映像の左右から色を取得します。プレイヤー追従はモニターで対象を選ぶか、卓を選択した照明リンクでプレイヤーを右クリックします。リンクを持って空中でShift＋右クリックすると自分を追従対象にできます。

照明の音声・映像解析は、再生開始者を優先して、再生できているクライアントから担当を1人選びます。担当者の退出や再生停止時は別のクライアントに引き継ぎます。結果と担当者の再生時刻をサーバー経由で共有し、往復の通信時間を補正した時計で照明へ反映します。同じ再生元を使う複数の制御卓でも結果を共有します。ライブ解析は回線遅延に応じて結果を待って補間するため、その分だけ照明の反応が遅れます。事前解析済みの区間には、この待機を加えません。

プレイリストの次の動画がローカルキャッシュへダウンロード済みなら、担当者が先に解析して結果を配信します。次の動画を優先し、その後に再生中のキャッシュ動画を解析します。先読みが間に合わない場合やライブ配信は再生中の解析を使います。事前解析は2時間までのキャッシュ動画が対象で、動画のダウンロード・再生・照明の描画は引き続き各クライアントで行います。

解析結果の同期には、この更新をサーバーと参加クライアントの両方に適用してください。

灯具・制御卓・再生機器は、Sableで組み立て・分解した後も同じ機器への接続を維持します。地上と構造物、異なる構造物の間でも照射とプレイヤー追従ができます。ビームは通常の壁や動く構造物の衝突形状で遮られ、未ロードのチャンクには照射を延ばしません。スポットの壁面光とプレイヤーの明るさにも遮蔽を適用します。広いコーンや光の面は複数のレイで近似するため、細かな形状の影は保守的に切り取ります。

## 照明のテストワールド

```powershell
.\gradlew.bat runClient -PlightingDemo
```

専用の実行フォルダー `run-lighting-demo` を使い、制御卓と灯具を配置したクリエイティブワールド「CMS Lighting Lab」を自動で作成して開きます。2回目以降は同じワールドを開きます。通常の `runClient` のワールドは別フォルダーに保存されます。

12灯を6グループに2灯ずつ接続済みです。G1はスポット、G2はビーム、G3～G5はレーザーの単線・扇・面、G6は映像の色とプレイヤー追従を試せます。同梱の60秒のテスト動画をローカルで再生するため、外部のメディアAPIの準備は不要です。デモ用コードと動画は通常のビルドには含まれません。

Sable入りの検証用ワールドは、次のコマンドで開きます。

```powershell
.\gradlew.bat runClient -PlightingDemo -PsableTests
```

`run-sable-lighting-demo` に分離し、Sable 2.0.6とNeoForge 21.1.228を使用します。通常の照明テストワールドは変更しません。

### 2クライアントで照明同期を確認する

Minecraft EULAに同意したら、リポジトリ直下で専用サーバーと2クライアントの設定を準備します。既存の設定と動画は保持します。

```powershell
python scripts/prepare_lighting_network.py --accept-eula
```

FFmpegが使える環境では同梱の動画を180秒に延長します。実行ファイルは `--ffmpeg` で指定でき、用意したMP4は `--media` で使えます。FFmpegが見つからず同梱の60秒動画を使う場合は、以下のGradleコマンド3つすべてに `-PlightingNetworkSeconds=60` を追加します。別の長さの動画を使う場合は、同じ設定にその秒数を指定します。

サーバーの起動を待ってから、2本のプロキシと2クライアントをそれぞれ別のターミナルで起動します。`CMS_Analyst` は25584、`CMS_Observer` は25585へ自動で接続します。サーバーは `127.0.0.1:25583` で待ち受け、ワールドやログは `build/lighting-network` に保存されます。

```powershell
.\gradlew.bat runAnalysisServer -PlightingNetworkTest
python scripts/lighting_latency_proxy.py --listen 25584 --target-port 25583 --control build/lighting-network/delay-a.json --log build/lighting-network/proxy-a.jsonl
python scripts/lighting_latency_proxy.py --listen 25585 --target-port 25583 --control build/lighting-network/delay-b.json --log build/lighting-network/proxy-b.jsonl
.\gradlew.bat runAnalysisA -PlightingNetworkTest
.\gradlew.bat runAnalysisB -PlightingNetworkTest
```

`delay-a.json` と `delay-b.json` を書き換えると、接続中に片道の遅延とジッターを変更できます。再生中に解析担当のクライアント側へ `prepare-next` を置くと、次の曲のキャッシュを配置できます。次の例ではAが担当です。

```powershell
'{"delay_ms":300,"jitter_ms":80}' | Set-Content build/lighting-network/delay-b.json -Encoding utf8
New-Item build/lighting-network/a/prepare-next -ItemType File
```

`server/lighting-network-server.jsonl` の `nextEnd` が `-1` から変わると、サーバーが次の曲の解析結果を受信しています。Aを終了すると、Bが解析を引き継ぐ様子を確認できます。

```powershell
New-Item build/lighting-network/a/disconnect -ItemType File
```

クライアントを終了し、`New-Item build/lighting-network/server/stop-test -ItemType File` でサーバーを停止します。プロキシは `Ctrl+C` で停止します。再試行前には `prepare-next`、`disconnect`、`stop-test` を削除し、遅延の初期値を制御ファイルで確認してください。
